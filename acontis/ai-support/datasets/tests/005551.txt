### ARTICLE00_SUBJECT
Hot Connect Topology Reload

### ARTICLE00_BODY
<div>
<p>Hi Cyril,</p>
<p> </p>
<p>Are you available to meet with Quinton, Paul and myself this week to discuss some design ideas for the implementation of our EtherCAT state machine?</p>
<p> </p>
<p>In making our EtherCAT master state machine more robust, we are considering the following design, some of which has already been implemented.</p>
<p> </p>
<ol start="1" type="1">
<li>A higher level EtherCAT master state machine that runs independently from Acontis’s CEcMaster::MasterStateMachine. Our internal state machine tracks the master state independently and uses a message queue to synchronize events from various sources including EC-Engineer, a user program in the controller, a PLC program and notification events from the Master/Slaves. Example events handled by our state machine may include…</li>
</ol>
<ol start="1" type="a">
<li>Apply EtherCAT configuration</li>
<li>Transition Master to OP</li>
<li>Accept topology change</li>
<li>Reset EtherCAT Network</li>
</ol>
<p> </p>
<ol start="2" type="1">
<li>It appears that we can disable automatical topology change mode using EC_IOCTL_SB_SET_TOPOLOGY_CHANGE_AUTO_MODE. In this way we can prevent the topology changes from automatically happening until we are ready. This would ensure that the scanbus and DC init would be synchronized with other user requests. It looks like we can implement as follows…</li>
</ol>
<ol start="1" type="a">
<li>Use EC_IOCTL_SB_SET_TOPOLOGY_CHANGE_AUTO_MODE to set topology detection to manual mode.</li>
<li>Listen for EC_NOTIFY_HC_TOPOCHGDONE notification before enqueuing an event that will make a call to EC_IOCTL_SB_ACCEPT_TOPOLOGY_CHANGE synchronously. </li>
</ol>
<p> </p>
<ol start="3" type="1">
<li>Our state machine can monitor for notification events that can be used to handle error conditions.</li>
</ol>
<ol start="1" type="a">
<li>EC_NOTIFY_SLAVE_UNEXPECTED_STATE – Used to automatically correct the slave state after power-cycle.</li>
<li>EC_NOTIFY_SLAVE_ERROR_STATUS_INFO – Used to automatically reinitialize the master when slave errors prevent operation (enabled by user option).</li>
</ol>
<p> </p>
<ol start="4" type="1">
<li>Ideally, we would be able to synchronize our state machine with EC-Engineer actions that use the RAS connection to issue commands (Especially Scanbus). </li>
</ol>
<p> </p>
<p>Can you give us any insights and recommendations on this design? Alternative design ideas?</p>
<p> </p>
<p>Any thoughts on using manual vs automatic hot-connect logic? Will hot connect groups still work if we decide to purchase the hot connect feature later on?</p>
<p> </p>
<p>Thanks,<br>
<br>
