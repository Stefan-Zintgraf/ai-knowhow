I thought actually that Energid was getting integrated with Teradyne, which I know also owns UR, so I didn’t realize that actually Energid was going into UR. Either way I hope it is good for you!</div><div> </div><div>A working counter error is an EtherCAT error that occurs when a slave does not interact with the process data. So EC-Master is sending out the cyclic frame with a known working counter based on the configuration (number of slaves, mapped process data, etc.). Each slave will then decrement the working counter accordingly so that when the frame comes back to the master the working counter should be 0 and that means everything was as expected. So if something happens on the network and a slave doesn’t interact with the frame then it wouldn’t decrement the working counter and it wouldn’t be 0 when the frame got back to the master. So the WKC error doesn’t help so much in pinpointing the problem, but it indicates there was a problem.</div><div> </div><div>The frame loss error can be due to a couple of things. Most often this is due to the frame being sent out and the master timer task starting up again before the frame is received back. The cause of this is due to the the frame taking too long to go around the network in the given cycle time. This could be because the cycle time is just too fast for how many slaves are in the network and how much data needs to travel around the network. It could also be because the jitter of the timing on the master system is too high, so sometimes the timer is shorter than expected by some significant margin and the frame isn’t back yet.</div><div> </div><div><a href="https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-b/software-integration.html#error-detection-and-diagnosis" rel="nofollow noreferrer noopener" target="_blank">https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-b/software-integration.html#error-detection-and-diagnosis</a></div><div> </div><div><a href="https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-b/api.html#emnotify-ec-notify-status-slave-error" rel="nofollow noreferrer noopener" target="_blank">https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-b/api.html#emnotify-ec-notify-status-slave-error</a></div><div> </div><div>Hope this helps, and happy to look at some log files or some more information from a network capture to further assist. Are you using any tool like EC-Engineer for diagnosis?</div><div>
