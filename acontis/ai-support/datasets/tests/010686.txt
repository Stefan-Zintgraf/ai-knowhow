Question about ecatConfigureMaster behavior

### ARTICLE00_BODY
<div dir="ltr">
<div>Hello</div>
<div> </div>
<div>I have a question about the behavior of <i>ecatConfigureMaster </i>function. We are using the 3.1 version of acontis master for arm CPU on linux.</div>
<div> </div>
<div>After the <i>ecatConfigureMaster </i>is executed the master state is UNKNOWN (0) and we always need to do another INIT or UNKNOWN -&gt;PREOP transition after calling it. Is there a way for the master to stay in PREOP state after configure? </div>
<div> </div>
<div>We would like to avoid going to UNKNOWN or INIT state during the runtime of our application because the transition back to PREOP takes around a second to do. We would only want to do it once at the start. But we need to call <i>ecatConfigureMaster </i>after modifying the size of the process image in the ENI file which can happen during the runtime of the application. </div>
<div> </div>
<div>Another solution I was thinking about is to remove some of the InitCmds from the ENI file after the first INIT-&gt;PREOP transition to avoid sending them all the time if not needed which would probably lower the transition time to PREOP after <i>ecatConfigureMaster </i>in case we can't avoid the UNKNOWN state after configure.<i> </i>
</div>
<div> </div>
<div>Thanks you for you response</div>

Hi Rok,<div><br></div><div>unfortunately not. The ENI defined InitCmds that have to be applied during the transitions.</div><div><br></div><div>It probably makes sense to not include the long run-once InitCmd from the ENI and send it manually  from the application during  the transitions.</div><div>It is possible to use <span>EC_IOCTL_ADD_COE_INITCMD to register a callback </span><span>m_pfnSlaveCoeInitCmdCallback that will be called for each CoeInitCmd and filter out the long InitCmd during the following startup procedures.</span>
