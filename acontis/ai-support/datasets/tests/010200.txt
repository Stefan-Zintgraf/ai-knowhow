Dear EtherCAT Support

Question about EC-Master(YUSHIN) [M107]

When trying to boot EC-Master (Core 3) and Linux (Core 0, 1, 2) simultaneously, both Linux and EC-Master attempted to access Ether, causing an error.
The issue was resolved by making ENET1 invisible to Linux.
However, when booting EC-Master and Linux together, a new problem occurred.
The following error message appeared on the Linux side, and Linux could no longer be controlled.

　root@imx8mpevk:~# [   36.926597] cpu cpu0: _set_opp_voltage: failed to set voltage (950000 950000 950000 mV): -110
　[   36.935156] cpu cpu0: Failed to set regulator voltages: -110
　[   36.940844] cpufreq: __target_index: Failed to change cpu frequency: -110
　[   37.366589] cpu cpu0: _set_opp_voltage: failed to set voltage (950000 950000 950000 mV): -110
　[   37.375144] cpu cpu0: Failed to set regulator voltages: -110
　[   37.380821] cpufreq: __target_index: Failed to change cpu frequency: -110

According to the explanation from the μC3 vendor, in order to avoid the above error,
they suggest commenting out the clock control in the clock_init() function in the attached hw_init.c.
However, in the hw_init.c provided by Acontis, it is already commented out.
We believe that the corresponding process for clock_init() might be handled elsewhere.

  (Q1) Is there a corresponding process for clock_init() implemented within the Acontis stack or elsewhere? If so, could the removed part be provided?
  (Q2) If there is any other information related to the error message in Linux, please let us know.

Best regards,
Takuya Fujikawa

Dear Mr. Fujikawa,<div><br></div><div>A1. No, there is no clock configuration for ENET1 in LinkLayer. There is already a LinkLayer parameter called 'bNoPinMuxing', but it does not affect IMX8MPlus anyway for there is no clock configuration for this chip in our software.</div><div>A2. Unfortunately we cannot give you any additional information concerning this particular Linux issue.</div><div><br></div><div>
