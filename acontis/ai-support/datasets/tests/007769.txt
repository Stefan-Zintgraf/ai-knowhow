Curly brace initialization of struct members like "StructType structName = {0}"

### ARTICLE00_BODY
<div>
<p>Hi Acontis Support,</p>
<p> </p>
<p>In code review I discovered some minor struct initialization code that in our code base would normally be cleaned up a bit. I want to be clear that the code is likely doing what is needed, but may be misleading for a developer.</p>
<p> </p>
<p>When a struct is initialized with a single zero in curly braces, like in several below cases, then the zero applies only to the first struct member. The remaining members are value initialized to zero if they are simple data types. When reading this code, it can sometimes be assumed that it is applying zero to all struct members however, it may not be the case if some of the members are not value initialized to zero.</p>
<p> </p>
<p>In EcDeviceIntelGbe.cpp:2234 and 2236.</p>
<p> </p>
<p>The below line initializes the first member of the struct to zero.</p>
<p>EC_T_LINK_FRAMEDESC oSendFrame = { 0 };</p>
<p> </p>
<p>Ideally the code would just initialize all struct members using value initialization which will be zero for almost all simple data types like my below example.</p>
<p>EC_T_LINK_FRAMEDESC oSendFrame = { };</p>
<p> </p>
<p>I’ve noticed other various other places in the EC-Master code base where this could get cleaned up.</p>
<p>EcMaster.cpp:14807</p>
<p>EC_T_LINK_FRAMEDESC oRxEtherCATFrame = {0};</p>
<p> </p>
<p>EcMaster.cpp:14816</p>
<p>EC_T_LINK_IOCTLPARMS oLinkIoCtlParms = {0};</p>
<p> </p>
<p>It may be that several engineers at Acontis are aware of this. But I just wanted to pass along this tip in case can be helpful.</p>
<p> </p>
<p>No support ticket necessary!</p>
