### ARTICLE00_SUBJECT
emDcsGetStatus documentation suggestions

### ARTICLE00_BODY
<div>
<p>Here are some recommendations for improvements to the documentation for emDcmGetStatus() (<a href="https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-a/dcm_api.html#emdcmgetstatus" rel="nofollow noreferrer noopener" target="_blank">https://public.acontis.com/manuals/EC-Master/3.1/html/ec-master-class-a/dcm_api.html#emdcmgetstatus</a>).</p>
<p> </p>
<p>Mainly, I think it could be improved to be clearer about how it behaves for each of the DCM modes, which in general look like this:</p>
<p> </p>
<ol start="1" type="1">
<li>
<b>BusShift</b> and <b>MasterShift</b> always return EC_E_NOERROR, but may have an error code in *pdwErrorCode. It would be nice if this was documented as such. I find it confusing that the documentation for pdwErrorCode refers to below in the return values. I recommend keeping return values and *pdwErrorCode values separate.<p></p>
</li>
<li>
<b>MasterRefClock</b> can return different values, but does not modify *pdwErrorCode. It should be documented that pdwErrorCode shall not be used for MasterRefClock mode. It also would be good to clearly document which return values can be seen in this mode, separate from what values can appear in *pdwErrorCode. <p></p>
</li>
<li>
<b>LinkLayerRefClock</b> (and others?) always returns EC_E_NOTSUPPORTED. This behavior should be documented.<p></p>
</li>
</ol> <p> </p>
<p>That is, which DCM mode is selected greatly affects how the caller should use this function, so it seems like that would be good to document.</p>
<p> </p>
<p>Thank you.</p>
