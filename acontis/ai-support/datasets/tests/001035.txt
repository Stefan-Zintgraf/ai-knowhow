### ARTICLE00_SUBJECT
EcMaster - non operational state if one station is missing during startup

### ARTICLE00_BODY
<div>
<p>Hi support team,</p>
<p> </p>
<p>After more tests on the EtherCAT master we have identified issues in the following case.</p>
<p>The network is composed of</p>
<ul type="disc">
<li>Master with cable redundancy<p></p>
</li>
<li>Station 1 : Beckhoff EK1100 + 8 modules<p></p>
</li>
<li>Station 2 : Beckhoff EK1100 + 3 modules, or WAGO 750-354 + 5 modules<p></p>
</li>
</ul> <p> </p>
<p>We start the master with only one of the 2 stations powered on (Station1), station 2 is OFF.</p>
<p>The bus scan reports a “Mismatch configuration error”.</p>
<p> </p>
<p><b>ISSUE1 : </b></p>
<p>The master cannot be set in operationnel state, the reported error by emSetMasterState is Bus configuration mismatch (0x9811001e)</p>
<p>The station 1 also remains in non operationnal state.</p>
<p>We expect the master to be able to reach the Operational state and also station 1 to be in operationnal state in this case.</p>
<ul type="disc">
<li>Is there a setting we can change to allow operational state whereas the bus real configuration mismatch the expected one ?<br>I have attached configuration file and logs for EK1100 + WAGO 750-354 test<p></p>
</li>
<li>Can you suggest a way to manage such a case from our source code ? Is it necessary to scan the network permanently until exact configuration match ?<p></p>
</li>
</ul> <p> </p>
<p><b>ISSUE2 : </b></p>
<p>When we power on station2, stations 1 and 2 remains in non operational state.</p>
<p>We expect of course master and both stations to be in operational state.</p>
<p>May be this second issue will be solved automatically when the first one is solved : We suppose this is because the master is not in OP state due to station 2 off during startup.</p>
<p> </p>
<p>These issues have a much greater impact than issue reported as Ticket #700743.</p>
<p> </p>
