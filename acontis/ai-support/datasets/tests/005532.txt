EC-Master Linux with Python root privileges

### ARTICLE00_BODY
Hi,<div> </div><div>We have a potential customer evaluating the EC-Master for Linux with the Python package. They are using the raw socket driver and they have come up with a way to provide root privileges without giving full root access by giving their application “cap_net_raw” capabilities. They mentioned that when they do this for a Python script it is a little strange because it means they're giving the Python executable in general those permissions, rather than their individual application.</div><div> </div><div>They are wondering if we are aware of how other users deal with this and what our suggestions are.</div><div>

### ARTICLE02_SUBJECT
EC-Master Linux with Python root privileges

### ARTICLE02_BODY
<div>Hi Jon,</div><div><br></div><div>What the customer can do is that they can create a virtual python environment. Preferably, they should do this in our package home directory:</div><div>cd Bin/Linux</div><div>
<mark>python3 -m venv --copies PyEnv/</mark><span style="color:rgb(41, 41, 41);"> </span><br>
</div><div>A new directory PyEnv will appear, Now they can activate the environment with the following command:</div><div><span style="color:rgb(41, 41, 41);">source PyEnv/bin/activate</span></div><div>
<span style="color: rgb(41, 41, 41);">They can now give "</span><span>cap_net_raw” capabilities to their python exe under </span>

<span style="color:rgb(41, 41, 41);">PyEnv/bin/</span> <span>!</span>
</div><div>The Python demo won't need any root priviliges when the environment is activated!</div><div><br></div><div>When the user quit the environment using the command deactivate. The original python under /usr/bin is again active and it has no "cap_net_raw" capabilities!</div><div><br></div><div>Of course for more security, Only the users who are going to start the python Demo should have access to the folder PyEnv! All others should be excluded!   </div><div><br></div><div>Mit freundlichen Grüßen</div><div>Haithem Jebali</div><div> <br><br>
