</div><div>
<span>This buffer should stay valid until </span><span>emMbxTferDelete() is called.</span>
</div><div>
<div><br></div>
<div>EC_T_MBXTFER_DESC.pbyMbxTferDescData will be copied to EC_T_MBXTFER.pbyMbxTferData. Between emMbxTferCreate() and emMbxTferDelete() you should only access to EC_T_MBXTFER.</div>
<div><br></div>
</div><div>
<span>Depending on the SDO transfer Upload or Download, the data are copied from or to </span><span>EC_T_MBXTFER.pbyMbxTferData.</span>

### ARTICLE02_SUBJECT
SDO mailbox transfers in acontis sdk

### ARTICLE02_BODY
Hi Martin/Jon,

Not sure if you're the right people to ask about this, but I have a question regarding mailbox handling for SDOs in the acontis stack. I am unable to figure this out based on the example code and documentation.

Specifically, what are the relationships between the two data pointers in the structs EC_T_MBXTFER_DESC and EC_T_MBXTFER?

Your example code and documentation does not appear to show code accessing the data returned to the master from an SDO upload request. The documentation also does not make it clear whether SDO download data should go in:

    EC_T_MBXTFER_DESC.pbyMbxTferDescData

or

    EC_T_MBXTFER.pbyMbxTferData

Page 330 shows SDO download example code allocating a 10-byte buffer at EC_T_MBXTFER_DESC.pbyMbxTferDescData but then placing the SDO data in the EC_T_MBXTFER.pbyMbxTferData pointer.

But then your SDO download example code on page 349 shows allocating a 4-byte buffer at EC_T_MBXTFER_DESC.pbyMbxTferDescData, and writing four bytes back to that same buffer, **not** EC_T_MBXTFER.pbyMbxTferData

Further, your SDO upload example on page 354 shows allocating a 4 byte buffer at EC_T_MBXTFER_DESC.pbyMbxTferDescData but then never using or freeing that buffer. 

Is EC_T_MBXTFER_DESC.pbyMbxTferDescData even used for SDO uploads? Does that buffer even need to be created? The documentation implies that the SDO response should be in EC_T_MBXTFER.pbyMbxTferData, and that buffer is managed/owned by the ethercat master.

Yet further, the documentation also seems to imply that both of those buffers are in/out data.

So, basically: what goes where and who owns what? 

The documentation appears to be contradictory and the example code appears incomplete.

Thanks,

-Andy
