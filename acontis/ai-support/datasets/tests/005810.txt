<p>Our team is investigating the source of a cycle “delay” in our EtherCAT systems that we haven’t been able to make heads or tails of and I was hoping you might have some insight. In a nutshell, we’re noticing that at any set cycle time on the EC-master, writes to physical outputs seem to not be reflected in corresponding input values until 2 cycles following the write as opposed to the 1 cycle which should be expected per our current understanding. For example, a command is written on cycle 0 at 100 Hz (t = 0 ms), the feedback does not read in as changed until cycle 2 (t = 20 ms). If we increase cycle time to 100ms, feedback still takes until cycle 2 (t = 200 ms). Our specific testing set-up is using a Beckhoff CX5140 flashed with a low-latency Ubuntu kernel, EL2042 digital outputs, EL3174-0032 analog inputs, and EL1002 digital inputs, but has been consistent with other controllers as well.</p>
