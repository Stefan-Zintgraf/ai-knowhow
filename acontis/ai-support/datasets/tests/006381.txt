<div>
<p>Dear Acontis Support Team,</p>
<p> </p>
<p>I am currently using your ecmaster version 3.1.4.99, for Linux x86 and I have encountered an issue concerning Cyclic Command WKC errors when attempting to execute emSetSlaveState with the timeout parameter set to EC_NOWAIT. The function works and changes the state of the slave, but it returns WKC errors while using it.</p>
<p> </p>
<p>Could you please advise if this is a known issue or limitation within this specific version of your library?</p>
<p> </p>
<p>To elaborate this more, this is the reply I got:<br> Cyclic command WKC error: Command = LWR, Address (ADP/ADO) = 16777216, Actual WKC = 1, Set WKC = 2</p>
<p>Cyclic command WKC error: Command = LWR, Address (ADP/ADO) = 16777216, Actual WKC = 1, Set WKC = 2</p>
<p>Cyclic command WKC error: Command = LWR, Address (ADP/ADO) = 16777216, Actual WKC = 1, Set WKC = 2</p>
<p>Cyclic command WKC error: Command = LWR, Address (ADP/ADO) = 16777216, Actual WKC = 1, Set WKC = 2</p>
<p>Cyclic command WKC error: Command = LWR, Address (ADP/ADO) = 16777216, Actual WKC = 1, Set WKC = 2</p>
<p> </p>
<p>And this is the pseudo code I have:</p>
<p>const EC_T_DWORD res = emSetSlaveState(0, 1003, newState, EC_NOWAIT);</p>

<div>Hi Marlon,</div><div><br></div>If you get the WKC error during the transition only, it could means that the slave change its state to the upper one but is not ready to process the cyclic frames. In this case you can ignore this notifications.<div>If you get them after the transition randomly. It could mean that you have some cycle accuracy issue.<br><div><br></div>
