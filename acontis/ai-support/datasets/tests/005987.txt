### ARTICLE00_SUBJECT
Software/Hardware Diagnostics suggestion

### ARTICLE00_BODY
<div>
<p>In V3.8.1, we found the new help icons after “Software Diagnostics” and “Hardware Diagnostics” to be confusing.</p>
<p> </p>
<p>It looked to us like the user would receive information on what the feature is (rather than analysis on the information actually shown). We were particularly confused when there were no errors and the “help” buttons were shown but did nothing.</p>
<p> </p>
<p>After understanding what the feature is, we decided to move this button to a new location with the text “Analyze”. Another possible name for this button would be “More Info”. This seems easier to understand, especially when it is disabled because there are no errors.</p>
<p> </p>
<p><img style="max-width:100%;width:5.0312in;max-height:2.7291in;width:483px;max-height:262px;" src="/api/v1/ticket_attachment/5987/31921/132723?view=inline" alt="A screenshot of a computer

Description automatically generated"></p>
<p> </p>
<p>I have attached our updated copy of <b>SlaveDiagGeneralTabView.xaml</b>.</p>
<p> </p>
<p>Notice that it there is a small bug that becomes visible with this change. The bug is that the enable/disable status of the Analyze button is not updated when errors are cleared using the Acknowledge button. The Analyze button gets left enabled even though there are no errors.</p>
<p> </p>
<p>Are you guys interested in adopting this alternate interface for the additional info? It is OK if not, of course. We can just have the different XAML in our product.</p>
<p> </p>
<p><b>Question:</b> Does the “Acknowledge” button only acknowledge Hardware Diagnostics errors? Or does it also acknowledge Software Diagnostics errors? If it does both, then its position under “Hardware Diagnostics” might be confusing.</p>
<p> </p>
<p>Thank you.</p>
