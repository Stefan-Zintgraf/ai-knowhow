Raspberry Pi 4

### ARTICLE01_BODY
Hi Francesco,<div><br></div><div><div><i><b>Anyway, I've run EC-Master Class A v3.1.1.02 without atemsys with the -sockraw eht0 option and the results are surprisingly good (provided I set the affinity of the eth0 IRQs on the core running Acontis software):</b></i></div></div><div>
<span>The performance is indeed very good. But I think our performance measurement don't show the whole truth.</span><br>
</div><div><span>The sockraw link layer is only a wrapper around the Linux raw sockets. This means the complete sending and receiving is done by Linux and not monitored within our performance measurement.</span></div><div>
<span>The bigger problem of the sockraw link layer is that we have no control about the actual send time of the frames. Linux decides when to send the frames. This leads to unpredictable delays between calling </span><span>ecatExecJob(eUsrJob_SendAllCycFrames) and the actual send.</span>
</div><div><br></div><div><div><b>1) have you consider supporting the Raspberry Pi 4 Compute Module?</b></div></div><div>No, we currently have no plans to support the embedded ethernet controller. <span>But in principle it would be possible for us to create a new link layer at the customer's request.</span>
</div><div><br></div><div>
<div><i><b>2) what are my best options at the moment?</b></i></div>
<div>Running sockraw doesn't require atemsys.<i><b><br></b></i>
</div>
<div>
<div>Personally, I would use the embedded ethernet controller as is for standard TCP/IP and a external PCIe network card for EtherCAT. As I saw the "<span>Compute Module 4 IO Board" comes with a PCIe x1 socket.</span>
</div>
