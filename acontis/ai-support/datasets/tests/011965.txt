</div><div dir="ltr">This question is from Mitsubishi (commission No. 40627).</div><div dir="ltr">
<br>
</div><div>When trying to open an ECC file created with a newer version using an older version of EC-Engineer, a “version not supported” error occurs and the ECC file cannot be opened.</div><div>Example:</div><div>Project file is not supported, because it was created by a newer version (Version: 3.9.1 [35], Expected: 3.8.3 [34]).</div><div dir="ltr">
<br>
</div><div>In this case, the above “34” and “35” are the values of the metadata (FileFormatVersion) stored in the ECC file, and our understanding is that EC-Engineer cannot open ECC files whose FileFormatVersion value is larger than the version it supports.</div><div dir="ltr">
<br>
</div><div>Regarding the metadata (FileFormatVersion) inside the ECC file, according to what rule or policy is this value incremented (updated) when the version is upgraded?</div><div dir="ltr">

Hi,<div><br></div><div>it is only upgraded if neccessary. So not every version will get an upgrade. </div><div>If it has to be upgraded, the second number of the version will change. The second number can also be changed for other reasons, but there will never be a version upgrade if only the third number is increased.</div><div><br></div><div>So 3.8.x -&gt; 3.9.0 --&gt; Upgrade possible</div><div>3.9.x -&gt; 3.9.x --&gt; Never an upgrade.</div><div><br></div><div>Best regards,</div><div>Kai <br><div data-signature="true" data-signature-id="2">
