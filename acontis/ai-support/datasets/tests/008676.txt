### ARTICLE00_SUBJECT
EC-Engineer Questions from US Plug Fest

### ARTICLE00_BODY
<div>
<p>Hi,</p>
<p> </p>
<p>I’m currently at the Plug Fest, and when testing one of the SubDevices without having the ESI file loaded, there was a prompt in EC-Engineer:</p>
<p> </p>
<p><img style="max-width:100%;width:6.4791in;max-height:3.3177in;width:622px;max-height:319px;" src="/api/v1/ticket_attachment/8676/48689/202066?view=inline"></p>
<p> </p>
<p>What is this feature? Is it searching on the internet for an ESI file? Is that what it is doing? If so, where is it searching from?</p>
<p> </p>
<p>When I selected yes, it used some auto-generated ESI file, but it was missing functionality compared to when I used the actual ESI file in a later test. Specifically, the mapped process data was empty, and there was no Modules tab despite the SubDevice using MDP.</p>
<p> </p>
<p>Another question:</p>
<p> </p>
<p>When I used the auto-generated ESI file and then went to Diagnosis mode, I was not able to read out the OD from the SubDevice (and there was no option to read the OD from ESI, but that seemed expected behavior considering it was using an auto-generated ESI).</p>
<p> </p>
<p>Why was it not possible to read the OD from the device when using the auto-generated ESI? Conversely, when I started without the ESI and selected “No” from the prompt about using an available online description, I was able to read out the OD from the device. It seems like this should be possible in either case just by trying to use the SDO Info service.</p>
<p> </p>
<p>/Jon</p>
</div>

<p>Hi,</p>
<p> </p>
<p>I’m currently at the Plug Fest, and when testing one of the SubDevices without having the ESI file loaded, there was a prompt in EC-Engineer:</p>
<p> </p>
<p><img style="max-width:100%;max-width:100%;width:6.4791in;max-height:3.3177in;width:622px;max-height:319px;" src="/api/v1/ticket_attachment/8676/48696/202079?view=inline"></p>
<p> </p>
<p>What is this feature? Is it searching on the internet for an ESI file? Is that what it is doing? If so, where is it searching from?</p>
<p>MG: It loads the information from the EEPROM (SII) and tries to create an ESI in memory.</p>
<p> </p>
<p>When I selected yes, it used some auto-generated ESI file, but it was missing functionality compared to when I used the actual ESI file in a later test. Specifically, the mapped process data was empty, and there was no Modules tab despite the SubDevice using MDP.</p>
<p>MG: MDP information is available in EEPROM. It just loads the PDOs. They should be available on PDO tab.</p>
<p> </p>
<p>Another question:</p>
<p> </p>
<p>When I used the auto-generated ESI file and then went to Diagnosis mode, I was not able to read out the OD from the SubDevice (and there was no option to read the OD from ESI, but that seemed expected behavior considering it was using an auto-generated ESI).</p>
<p>MG. Correct. CoE OD info is also not available in EEPROM. So it is also missing in the generated ESI. In DiagMode "Description from ESI" should be disabled. If slave supports "SDO Info", "Description from slave" should be enabled.</p>
<p> </p>
<p>Why was it not possible to read the OD from the device when using the auto-generated ESI? Conversely, when I started without the ESI and selected “No” from the prompt about using an available online description, I was able to read out the OD from the device. It seems like this should be possible in either case just by trying to use the SDO Info service.</p>
<p>MG: The information if slave has "SDO Info" will be also loaded from EEPROM info. In DiagMode, we use also the Master API to check if slave has "SDO Info" or not.</p>
<p><br></p>
<p>If you think there is a bug on loaded ESI data from EEPROM you can upload the EEPROM from slave and send me the file:</p>
<p><br></p>
