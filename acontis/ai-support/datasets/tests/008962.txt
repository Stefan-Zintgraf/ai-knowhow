<div>Hi Support Team,</div><div> </div><div>This is a question from Mitsubishi (commission No.40627).</div><div>This question is about the functionality of DCM, EC-Master.</div><div>Please refer the following questions from Mitsubishi and answer it.</div><div> </div><div>===</div><div>[Objective]</div><div>When the DC synchronization and the DCM synchronization are enabled and the communication cycle is increased from 1 ms to 8 ms, it is desired to operate while maintaining the accuracy of the DC synchronization.</div><div> </div><div>[Question]</div><div>Is there an appropriate way to set up EC-Master (DCM setting) or any know-how?</div><div>Or, if the communication cycle is lengthened, will the accuracy inevitably decrease?</div><div> </div><div>[Example]</div><div>I want to set the threshold for window monitoring of DC synchronization to 2us.</div><div>The above accuracy was achieved when the communication period was 1 ms. (Depends on Slave H/W)</div><div>In the case of DC+DCM synchronization, there is a high possibility that the accuracy of DC synchronization will be degraded after the correction of the reference clock by the Master. (Depends on Slave H/W and Master operation)</div><div>===</div><div> </div><div>Best regards,</div><div>Yuichi</div><div> </div><div>

A question from Mitsubishi about DCM functionality, EC-Master (QNo.94)

### ARTICLE01_BODY
Hi Yuichi,<div><br></div><div><blockquote>
<div>With DC synchronization alone, there is a reasonable chance that accuracy (as above) can be maintained. (Depends on Slave H/W)</div>
<div>In the case of DC+DCM synchronization, there is a high possibility that the accuracy of DC synchronization will be degraded after the correction of the reference clock by the Master. (Depends on Slave H/W and Master operation)</div>
</blockquote></div><div>Yes, the system time difference between the reference clock and the rest of the network can be impacted by the cycle time yes in case of BusShift.</div><div><br></div><div>The DC synchronization is triggered by write access to the 0x910 register. Running with 8ms means less access. We have a mechanism to add write access.</div><div><br></div><div>This can be controled with this parameter (set to EC_FALSE):</div><div>
<span>EC_T_DC_CONFIGURE::</span><span style="color:rgba(0, 0, 0, 0.87);">bAcycDistributionDisabled</span><br>
</div><div><div><a href="https://public.acontis.com/manuals/EC-Master/3.2/html/ec-master-class-a/dc_api.html?highlight=dcconfigure#_CPPv417EC_T_DC_CONFIGURE" title="https://public.acontis.com/manuals/EC-Master/3.2/html/ec-master-class-a/dc_api.html?highlight=dcconfigure#_CPPv417EC_T_DC_CONFIGURE" rel="nofollow noreferrer noopener" target="_blank">https://public.acontis.com/manuals/EC-Master/3.2/html/ec-master-class-a/dc_api.html?highlight=dcconfigure#_CPPv417EC_T_DC_CONFIGURE</a></div></div><div><br></div><div>Combined with more acyclic frames:</div><div>
<span>EC_T_INIT_MASTER_PARMS::</span><span style="color:rgba(0, 0, 0, 0.87);">dwMaxAcycFramesQueued</span><br>
</div><div><br></div><div>Using these parameters, EC-Master fills the unused acyclic bandwidth with frames distributing the system time. They can run a test by increasing <span>dwMaxAcycFramesQueued and check that </span><span>bAcycDistributionDisabled is EC_FALSE.</span>
</div><div><br></div><div>Best Regards,<br><div data-signature="true" data-signature-id="2">
