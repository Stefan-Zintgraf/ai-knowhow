### ARTICLE00_SUBJECT
Stack 3.1.3.01 -> Simulator Verhalten bei SDO write

### ARTICLE00_BODY
<div>
<p>Hi,</p>
<p> </p>
<p>seit dem Umstieg auf die Stack/Simulator Version 3.1.3.01 (vorher: 3.1.1.09) stellen wir in einem unserer Nightly Testcases folgendes geändertes Verhalten fest:</p>
<p> </p>
<ul type="disc">
<li>Simuliert wird ein 053-1EC01 MDP Slave mit einigen Modulen (ENI/EXI im Anhang)<p></p>
</li>
<li>Es wird ein SDO write auf den Slave gemacht, Index 0x3100 Subindex 2<p></p>
</li>
<li>Dieses Objekt existiert bei diesem Slave nicht, da es die Parameter für das MDP Modul auf Slot 0 enthält, das dort gesteckte Modul hat allerdings keine Parameter (einfaches DI)<p></p>
</li>
<li>Der Testcase erwartet entsprechend, dass der SDO write mit Fehlercode 0x9811004A zurückkehrt<p></p>
</li>
</ul>
<ul type="disc">
<li>Dies war bisher auch so, seit der neuen Version kommt allerdings 0x0 zurück<p></p>
</li>
<li>Bei Verwendung des selben ENI-Files mit dem echten Slave (kein Simulator), kommt wie erwartet 0x9811004A zurück<p></p>
</li>
</ul> <p> </p>
<p>Ist dies ein Fehlverhalten oder gibt es eine andere Erklärung dafür?</p>
<p> </p>
<p>Danke + Grüße</p>
<p>Bernd</p>
