### ARTICLE00_SUBJECT
EC-Master - Automatic Topology Update Feature Request

### ARTICLE00_BODY
<div>
<p>Hi Acontis Support,</p>
<p> </p>
<p>When using EC-Master with automatic topology turned on, it requires the master to at least achieve INIT state before it will automatically process topology updates. This means that EC-Master cannot automatically detect and recover a master that has a topology mismatch at startup, but then gets cable corrected after startup.</p>
<p> </p>
<p>For example, CAtEmInterface::McStateMachine() has the following code which explicitly blocks automatic topology updates while the master state is UNKNOWN.</p>
<p> </p>
<p> <span style="color:blue;">if</span> (bTopologyChangedDetected || bDlStatusIrqDetected)</p>
<p>{</p>
<p> <span style="color:green;">/* ignore topology changes if master is in UNKNOWN state */</span></p>
<p> <span style="color:blue;">if</span> (DEVICE_STATE_UNKNOWN == m_oAtEcatDesc.poMaster-&gt;GetMasterDeviceState())</p>
<p>{</p>
<p>m_oAtEcatDesc.poMaster-&gt;m_pBusTopology-&gt;TopologyChangeDone();</p>
<p>bTopologyChangedDetected = EC_FALSE;</p>
<p> </p>
<p>m_oAtEcatDesc.poMaster-&gt;SetDlStatusIrqDone();</p>
<p>bDlStatusIrqDetected = EC_FALSE;</p>
<p>}</p>
<p>}</p>
<p> </p>
<p>During experimentation, I commented out the above code and verified that topology updates can come through when the master state is still UNKNOWN (albeit with various errors).</p>
<p> </p>
<p>Please consider supporting one of my feature ideas here to allow us to provide this experience on startup.</p>
<p> </p>
<ol start="1" type="1">
<li>Consider a new feature that allows processing of automatic topology updates when the master state still UNKNOWN due to topology mismatch, but is otherwise ready to move into INIT.</li>
<li>Consider a new feature that returns a new notification in this case where topology changes are detected but cannot be processed because the master state is UNKNOWN.</li>
</ol>
<p> </p>
<p>Thanks,</p>
