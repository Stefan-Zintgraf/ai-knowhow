### ARTICLE00_BODY
<div>
<p>Dear,</p>
<p> </p>
<p>I have integrated the possibility to have multiple Ethercat master on our linux-based system but we are having some issues with some system in production.</p>
<p>This is in particular a test machine with 2 stations, which means that it can tests 2 Device Under Test at the same time.</p>
<p>The 2 stations are controlled by the same linux-based machine and for each station we are running a different Ethercat Master responsible for the Ethercat network of the station.</p>
<p>Each station has a Ethercat cycle time of about 1 kHz with incoming signals at 10 kHz (with oversampling).</p>
<p> </p>
<p>If we activate only 1 ecat master (and therefore only 1 station), we have a quite constant delay between a “requested current for a valve” (requested via CAN bus) and a “measured pressure on the same valve” (retrieved via Ethercat). This is expected.</p>
<p>Unfortunately if we activate the second EtherCat master, sometimes (but not always) we have an additional delay of 50 ms (which unfortunately makes our configuration unusable).</p>
<p> </p>
<p>The Ethercat master run isolated on CPU 2.</p>
<p>Kernel 4.4.256 with rt214 patch.</p>
<p>Acontis EC-Master-V3.0.3.03-Linux_x86 with I8254x.</p>
<p> </p>
<p>We are measuring the max jitter experienced by the master and we are usually on average around 32 us with peak at 600 us, therefore nothing which can justify a 50 ms delay.</p>
<p>Among the doubt that I have is our implementation of the multimaster.</p>
<p>We are <b>not</b> using the multimaster API approach (with one application calling the Acontis API passing every time the master number – e.g. emXXXX() ) but we are starting twice the same application and for each application instance, we initialize the master providing also the PCI address of the network card.</p>
<p> </p>
<p>It usually works without issue, apart from this machine.</p>
<p>Maybe our multimaster approach is wrong or there is some other investigation approach that you might suggest to understand what is causing this delay (maybe some special Linux command).</p>
<p> </p>
<p>I kindly ask if any of you could call me at your earliest convenience so that we can arrange an online meeting to discuss the issue.</p>
