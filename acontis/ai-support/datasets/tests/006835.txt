### ARTICLE00_SUBJECT
Seeking advice: EC-Master and atemsys linux driver

### ARTICLE00_BODY
<p>Hello,<br>
</p><p><br>
</p><p>I'm contacting you seeking advice regarding the configuration of the EC-Master stack on a linux platform.<br>
</p><p>I'm using a PC with the following configuration:<br>
</p><ul dir="">
<li>CPU: x86 - 64</li>
<li> OS: Debian 11<br>
</li>
<li>ethernet port 1: Intel I219-V (linux driver e1000e) =&gt; I use this one for EtherCAT<br>
</li>
<li>ethernet port 2: Intel I211 (linux driver igb)<br>
</li>
</ul>
<div>I need port 1 to be bound to the atemsys driver instead of e1000e. For reasons (*see below), I don't want to use the modprobe blacklisting mechanism.</div><div> </div><div>I therefore use the following configuration for modprobe:<br>
</div><div>options atemsys AllowedPciDevices="0000:00:1f.6" =&gt; limit atemsys to ethernet port 1<br>
</div><div>softdep e1000e pre: atemsys =&gt; make sure atemsys is loaded before e1000e so it can "steal" the device<br>
</div><div> </div><div>It partially works:<br>
</div><div>
<ul>
<li>after changing modprobe configuration and rebooting the PC, ethernet port 1 is bound to atemsys, ethernet port 2 is bound to igb -&gt; as expected<br>
</li>
<li>however, port 1 physical layer is down : the ethernet 1 port LEDs stay off<br>
</li>
<li>what is really strange: if I unload both e1000e and atemsys drivers, then load e1000e driver (I think it does something to configure the PHY), then unload the e1000e driver, then reload the atemsys and finally I do a SHUTDOWN (a reboot isn't enough) and restart, the EtherCAT port is now operational and stays operational after subsequent restarts.<br>
</li>
</ul>
</div><div> </div><div>Is this an issue you have experienced ? Is there something special to do to wake up the physical layer when using atemsys ?<br>
</div><div> </div><div>*Reasons for not blacklisting e1000e: I need to support another PC configuration where both ethernet ports are driven by I219 chips, therefore I can't blacklist e1000e.<br>
</div><div> </div>Best Regards,<br>
<div>Jerome Souquieres<br>
</div><div> </div><div>

### ARTICLE01_BODY
<div>Hi Jerome,</div><div>Atemsys is just for the connection between Linux Kernel Space to your EcMaster Application.</div><div>Without the Master Application there are only some minor Pcie power management things.</div><div><br></div><div>For me it's impotent, if</div><div>- EcMaster is working after unloading <span>e1000e</span><span> driver/kernel module.</span>
</div><div>- EcMaster is working when e1000e driver/kernel module was not loaded before.<span><br></span>
</div><div>- <span>e1000e</span><span> driver/kernel module can be reloaded, after unbind </span><span>e1000e</span><span> and after unbind atemsys.</span>
