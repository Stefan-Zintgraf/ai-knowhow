### ARTICLE00_SUBJECT
Bus Scan

### ARTICLE00_BODY
<div>
<p>Hi Support,</p>
<p> </p>
<p>I am trying to better understand how Bus Scan works in EcEngineer. In EcDevice::ScanWithNotifications(…), I see that we only configure the master when <i>!rasIsConfigured </i>is true. This corresponds to the master not having an ENI file downloaded. Calling ConfigureMaster(true) results in GenPreOp being called. This works best for us when we change our network. </p>
<p> </p>
<p>Questions:</p>
<ul type="disc">
<li>Why shouldn’t you invoke GePreOp when doing a network scan?</li>
<li>When you start a network scan, EcEngineer indicates that all slaves will be removed. Does this process preserve any slave data? For example, you only added one slave?</li>
</ul>
<p> </p>
<p>I’m trying to better understand how the Bus Scan works. If you could provide a general overview of how EcEngineer performs a network scan, that would be great!</p>

### ARTICLE01_SUBJECT
Bus Scan

### ARTICLE01_BODY
Hi Paul,<div><br></div><div>you have to look at that on an other way: we always use ConfigureMaster(true). Just not if we scan a configured RAS master. So you have to invoke GenPreOp ENI when you doing a network scan. </div><div>"RasIsConfigured" means that there is a Master running with an ENI file and we try to scan the running system over RAS. So we would override the running configuration with GenPreOpEni and that should not be done. </div><div>But if you scan a RAS master without an ENI file or your local master, then you should always call GenPreOpEni.</div><div><br></div><div>If you scan the network all information from your config will be gone. For the case that you just want to add one slave, we have the Edit Topology Dialog under the Network Menu. There you can scan and merge the result into your existing config.</div><div><br></div><div>Best regards,</div><div>Kai <br><div data-signature="true" data-signature-id="2">
