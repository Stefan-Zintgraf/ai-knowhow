### ARTICLE01_SUBJECT
Cyclic frames not received

### ARTICLE01_BODY
<div>Hi,</div><div><br></div><div>1) possible reasons for a missing response of a cyclic frame are:</div><div>- timing task is broken.</div><div>- <span>the frame was not received (due to bus problems)</span>
</div><div>- <span>too many or too long acyclic frames are sent in between sending cyclic frames by the master due to an improper configuration. </span><span>To avoid these error notifications the configuration may be changed as follows:</span><div>    1) lower value for master configuration parameter dwMaxAcycCmdsPerCycle</div>
<div>    2) Use a higher cycle time</div>
<br>
</div><div>2) <span>bAllCycFramesProcessed: </span><span>This flag is set to a value of `EC_TRUE` it indicates that all previously initiated cyclic frames (eUsrJob_SendAllCycFrames) are received and processed within this call. If it is set to 'EC_FALSE', it means that there was at least a frame loss.</span>
</div><div><span><br></span></div><div>
<span>if </span><span>OsWaitForEvent returns a timeout. It means that the event that is triggering the cycle time did not occur. It means the timing task is not working properly. In this case </span><span>bAllCycFramesProcessed will be probably false.</span>
</div><div><span><br></span></div><div>
<span>3) </span><span>EC_NOTIFY_FRAME_RESPONSE_ERROR</span><span>  will be also generated if 1 of 3 frames is not received. </span><span> </span>
</div><div>
<span>EC_E_TIMEOUT. </span><span>EC_NOTIFY_FRAME_RESPONSE_ERROR</span><span> </span><span> is probably an implication of OsWaitForEvent returning </span><span>EC_E_TIMEOUT.</span>
</div><div><span><br></span></div><div><span>Please control your timing task.</span></div><div><span><br></span></div><div data-signature="true" data-signature-id="2">
