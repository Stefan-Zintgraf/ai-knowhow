<p>Hi Jon,</p>
<p> </p>
<p>I noticed that EC-Master does some magic with the cyclic BRD command of the system time difference register (0x92C) for sync window monitoring. It appears that the BRD command is replaced by FPRD which addresses each DC-capable devices in the network sequentially.</p>
<p> </p>
<p>I noticed this because while doing some timing tests with EC-Master configured for master-shift, the system time difference of the EK1100 in the following configuration (upstream of the reference clock) was returning unexpected values:</p>
<ul type="disc">
<li>EC-Master <ul type="circle">
<li>EK1100 &lt;- invalid system time difference values <ul type="square">
<li>ELXXXX &lt;- reference clock</li>
<li>ELXXXX</li>
<li>…</li>
</ul>
</li>
</ul>
</li>
</ul>
<p> </p>
<p>The EK1100 is upstream of the reference clock and therefore isn’t receiving the system time which is propagated to the downstream devices. As a result the value in the system time difference register does not appear to be valid.</p>
<p> </p>
<p>I see that EC-Master overcomes this by replacing the BRD 0x92C command with FPRD of the specific slaves with DC enabled. This enables sync window monitoring to function even in the above scenario.</p>
<p> </p>
<p>Using TwinCAT the user must manually overcome this issue by enabling the EK1100 to be used as the reference clock (<a href="https://download.beckhoff.com/download/Document/io/ethercat-terminals/ek110x_ek15xxen.pdf" rel="nofollow noreferrer noopener" target="_blank">https://download.beckhoff.com/download/Document/io/ethercat-terminals/ek110x_ek15xxen.pdf</a> – page 43). This way the system time difference register of all devices is valid and the broadcast read of the system time difference registers returns a useful value. Enabling the EK1100 to be used as a reference clock does not appear to be supported in EC-Engineer.</p>
<p> </p>
<p>Is my understanding of EC-Master’s behavior correct? Is this behavior selectable (BRD vs FPRD)? Are there any other details we should be aware of? Can you provide any other details about why this approach was implemented?</p>
<p> </p>
<p>Regards,</p>
<p>Cameron</p>
