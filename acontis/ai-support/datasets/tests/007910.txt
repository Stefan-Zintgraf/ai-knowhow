<p>I am thinking using a RAS notification mechanism to periodically send a message from a client(running on Windows) to the server(master stack running on VxWorks).</p>
<p>For instance</p>
<ul type="disc">
<li>RAS client: a remote application running on windows sends a message by calling emNotify(masterId, code(&gt;0x0000FFFF), EC_T_NOTIFYPARAM)</li>

</ul>
<p> </p>
<p>My questions</p>

<li>When does the master posts the notification/call notificationCallBack in regarding to the message receiving from the client in the below sequence</li>
<ol start="1" type="a">
<li>ecatExecJob( eUsrJob_ProcessAllRxFrames)</li>
<li>ecatExecJob( eUsrJob_SendAllCycFrames)</li>
<li>ecatExecJob( eUsrJob_MasterTimer)</li>
<li>ecatExecJob( eUsrJob_SendAcycFrames)</li>
</ol>
</ol>
<p>Other words, does the master post the notification before (a) or after (a) or before(b) or after(b), or … ?</p>
<p> </p>

Hi Thao,<div><br></div><div>the notifications are generated from the RAS server thread and are not synchronized with the jobs. We introduced this API to control the EC-Motion application remotely. We send commands and read status. I don't see any issue using it. If you need to synchronize it with the jobs. You need to introduce a FIFO in between.</div><div><br></div><div>Best Regards,<br><div data-signature="true" data-signature-id="2">
