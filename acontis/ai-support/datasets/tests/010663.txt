### ARTICLE01_SUBJECT
Some questions about Copy and Paste SubDevices (PNo.30)

### ARTICLE01_BODY
Hi Yuichi,<br><br>I remember this problem, it is not so clear, but I will try to explain why is it like this.<br><img style="max-width:100%;width: 379px;max-width: 100%;" src="/api/v1/ticket_attachment/10663/61097/254315?view=inline"><br>The user wants to copy Subdevices 1001-1003 and wants to paste them between the MainDevice and the first Subdevice(1001)<br>The selected output port of parent is easy to understand, the user wants to paste them as "Children" of the MainDevice.<br> Now the not so clear part, "Selected output port is already connected, select new output port" is basically, there were some SubDevices already connected to the port we selected, where does the user wants to connect the Subdevices that were originally conected to this port on the MainDevice. So we have two cases:<br>
Case 1 (Green):  In this case, the port 1 of the "copied version" of SubDevice_1003 is empty, so selecting this port should not cause any issues. The original SubDevices will be reconnected to the selected port of the new pasted SubDevice. <br>Case 2 (Red): In this case, the port 2 of the "copied version" of SubDevice_1001 is already connected to port 0 of the "copied version" of SubDevice_1003, so trying to reconnect the original SubDevices to this port will cause the original SubDevices to "float as unconnected". If the pasted SubDevice that was connected to the selected port is deleted, then the original SubDevices will be reconnected to the selected port.<br>
After pasting the SubDevices, the copied SubDevices recieved a new unique ID. 

But before that, they are just copies of the original devices.<br><br><div>Best regards</div><div data-signature="true" data-signature-id="2">
