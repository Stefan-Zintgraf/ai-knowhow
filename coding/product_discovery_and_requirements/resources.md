# Resources

**Status:** First draft

This is a curated starting point rather than an exhaustive bibliography. Prefer primary sources and methods that help a team make and test decisions.

## Suggested reading path

1. **Continuous Discovery Habits — Teresa Torres**  
   A practical operating model for continuous customer contact, opportunity mapping, assumption testing, and product-team collaboration.

2. **User Story Mapping — Jeff Patton, Peter Economy**  
   Connects user journeys, product conversations, and coherent incremental releases.

3. **Writing Effective Use Cases — Alistair Cockburn**  
   A precise, implementation-neutral approach to actor goals, success paths, and extensions.

4. **Software Requirements, 3rd ed. — Karl Wiegers, Joy Beatty**  
   Broad practical coverage of elicitation, analysis, specification, validation, and management.

5. **Testing Business Ideas — David J. Bland, Alexander Osterwalder**  
   A catalog of experiments for testing desirability, feasibility, and viability assumptions.

6. **Domain-Driven Design Distilled — Vaughn Vernon**  
   A short bridge from domain discovery into strategic and tactical domain design.

## Practical technique index

| If the uncertainty is about…                 | Start with…                                            |
| -------------------------------------------- | ------------------------------------------------------ |
| Whether a problem is valuable                | Interviews, observation, JTBD, current-journey mapping |
| Which opportunity to pursue                  | Opportunity Solution Tree, outcome mapping             |
| Whether a proposed solution will work        | Assumption mapping and targeted experiments            |
| End-to-end product scope                     | User story mapping                                     |
| Complex actor interactions                   | Use cases and scenario walkthroughs                    |
| Tacit business behavior                      | EventStorming, Domain Storytelling, example mapping    |
| Conflicting terminology or ownership         | Glossary, capability map, context map                  |
| Architectural risk from non-functional needs | Quality-attribute scenarios and utility tree           |
| Contractual or regulated completeness        | Requirements engineering and traceability              |

## Evaluation rule

Adopt a method when it reduces an important uncertainty or improves a consequential decision. Do not adopt it solely because its artifact looks complete. Scale ceremony with risk, irreversibility, regulation, coordination cost, and product lifetime.
